### F297. A range read cannot check a whole-file hash

- **Why:** OneDrive gives a hash for the whole file, not each requested range.
- **Effect:** A range read takes an answer whose `ETag` and size are the eTag and size the
  store holds with the opened content, or else checks the opened metadata version before and
  after the body; every range of an opened content is held to the first one's version, and a
  change fails the read with ESTALE. This depends on OneDrive correctly binding its eTag,
  metadata and download response to the content; individual ranges cannot independently
  prove that binding by a whole-file hash. Unfinished whole-download staging is never read.
- **Stays because:** Hashing a whole file before its first byte would require downloading
  every file whole, including files too large for the available local space.
- **Where:** `crates/konedrived/src/mount/item_range_fetcher.rs`,
  `crates/konedrived/src/content_source/graph_source.rs`
