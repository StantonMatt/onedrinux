### F298. A backing-directory change while the daemon is absent is not a cloud move or removal

- **Why:** A copy, restore and torn disk operation can leave the same backing picture as a
  deliberate move or removal. Recovery cannot safely guess the user's namespace intention.
- **Effect:** Missing copies never delete in OneDrive; an unrecorded move can leave a new copy
  and re-show the original. Recovery without rows hashes every file, ignoring stale cTag marks.
  Open writers are always changed; changed-here rows compare nanoseconds. With a retained
  hashed row, an offline edit preserving size and whole-second time can still go unnoticed.
- **Stays because:** Guessing moves or removals could delete another device's work. Deliberate
  namespace changes must go through the running mount.
- **Where:** `crates/konedrived/src/mount/backing_directory_check/disk_finding.rs`, `row_writer.rs`.
