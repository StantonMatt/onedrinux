### F302. A removal made here is sent to OneDrive with no local trash and no confirmation

- **Why:** OneDrive keeps what is removed in its own recycle bin. A trash inside the folder would
  be uploaded, and a hold that waits for a confirmation depends on a window being open.
- **Effect:** A file or a whole directory tree removed in the sync folder is removed in OneDrive as
  any other change is sent, after the removals' quiet time of thirty seconds. Only a burst over
  the change guard's limits waits for the user, on On Hold. A directory removal waits for a
  listing of its own, is held back when that listing shows anything new or changed below the
  directory, and is sent with the folder's eTag; a 412 (the folder renamed or moved in OneDrive)
  keeps it. What another device puts in the directory between that listing's read of it and the
  removal goes to the recycle bin with it. It is got back from OneDrive's recycle bin, on the
  web. A removed file's bytes on this computer are set aside only while its removal waits or is
  held, so that Restore can put it back, and go once the removal is sent.
- **Stays because:** We chose one recycle bin, OneDrive's, over a second one here that would have
  to be kept in step with it.
- **Where:** `crates/konedrived/src/mount/item_write_operations/remove.rs`,
  `crates/konedrived/src/change_guard/`, `crates/konedrived/src/mount/upload_rules.rs`
