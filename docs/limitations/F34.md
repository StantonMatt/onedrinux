### F34. A file OneDrive gives without a hash cannot become a verified resident copy

- **Why:** A cTag identifies content but cannot verify the bytes downloaded for it.
- **Effect:** Whole downloads fail closed with EIO, retaining any old resident version. Range
  reads remain possible with stable version metadata; hydration for editing is refused. Upload
  completions without a hash require fresh metadata and otherwise hold the local generation.
- **Stays because:** OneDrive decides whether to supply quickXorHash. Accepting bytes without
  it as clean would make unverified content eligible for eviction or editing.
- **Where:** `crates/konedrived/src/content_source/source/guards.rs`,
  `crates/konedrived/src/onedrive_steps/content_upload.rs`
